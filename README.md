# Solar Fin 光路检查器

CWISA 2026 概念演示。以一条入射光的完整因果关系为入口，联动有限叶片、原幕墙、接收命中和城市位置。方向占比与角度评分已停用，不将数值守恒当作现场准确性。

## 使用

```sh
npm test
npm run build
python -m http.server 8765 --bind 127.0.0.1 --directory dist
```

测试与打包需要Node.js 22或更新版本，不需要安装依赖。也可以直接在仓库根目录开启静态服务器。

线上：https://the-unknown-01.github.io/curtainwall-glare-preview/

1. 默认中环街景视图；切换局部机制视图选择一条入射根，金色表示入射、橙色反射、蓝色透射。每条展示的入射根保留全部计算支路，不再做按楼宇名称的路径裁剪。
2. 点选分支树或使用交点前后按钮，检查三维入射角、局部R/T/A和父节点。侧视／俯视只是正交投影，不能从投影量取一般三维入射角。
3. 切换城市定位查看来源与去向。光束组最多绘制6棵完整树；线宽不是能量。接收命中点及列表可反查入射根与对应父交点。
4. 方案对比仅展示同一光源孔径下的采样和数值账目，不输出优劣评分。
5. 回放或导入实验角度记录；导出schema cwisa-demo/2，包括根、交互节点、段、终端、材料表面、光源孔径、能量账目和数据来源。

## 计算模型

`js/finite-optics.js`使用有限矩形交点计算。所有方案使用相同的光源平面：平面垂直于太阳方向，固定包围原幕墙及0–50度外屏运动包络，默认8×18个等权采样。入射能量归一化为1；这不是实测太阳功率。改变设备或相机不会改变采样。

每次真实命中薄板后，记录父节点和三维交点，并按有效R/T/A分配反射、透射与吸收。透射与反射光重新检测全部有限叶片、间隙、原幕墙及建筑遮挡，不再依靠无限平面推算出口或无条件乘T²。原幕墙后方透射在室内边界终止。

未知邻楼／屋面在首次接触时停止，不制造镜面第二跳；材料吸收、进入室内、接收面交付、到达前遮挡、未评估与追踪截断分别记账。深度上限8、每根入射的功率截止比例1e-5；被截断部分仍在账目中。每个分叉满足输入=反射+透射+吸收；全局输出账目与输入的差为残差。

## 参数与适用边界

- 零厚度薄板的恒定有效系数：外屏R=.12、T=.65、A=.23；原幕墙R由滑块设置，T=.60，A=1−R−T。均是假设的同一太阳波段参数，非实测VLT或角度／光谱曲线。
- 示例城市模块宽约3m、高3.15m、行距3.5m、铰链与幕墙间距0.6m。它们不是批准图则或实装尺寸。
- 几何反射方向和R/T/A记账具有合成场景回归测试；折射横向位移、厚玻璃层间路径、偏振、复杂散射、太阳有限角尺寸、真实玻璃和周边材料数据尚未接入。
- 接收图是点采样命中，不是有限光束足迹、照度、辐照度热图或眩光评价。城市采样分辨率与真实材料尚待现场验证，不能用当前结果宣称改造改善率或安全角度。
- 3D标注和线宽只帮助读图；段端点保持计算交点，不再整体抬高0.75m。局部视图只显示附近叶片，计算仍包含整面候选立面的全部叶片。
- 丝杠小图使用R02图纸的a=240、e=60、l=300mm、叶片L=600mm示例。它是独立机构比例示意，不能与城市模块尺寸混用采购。
- 本应用不连接或控制硬件，不宣称结构、抗风、消防或光学认证。内置实验角度为合成示例。

## 验证

`npm test`执行五组测试。新增有限光学测试覆盖：有限边缘与背向交点、三维反射定律、原幕墙返回光实际穿过叶片、间隙不被错误衰减、完整父子关系、逐节点及全局守恒、深度／功率截断、前置遮挡、未知材料停止、公共光源孔径、设备采样一致、均匀合成场景的网格细化一致性。

这些验证不等于城市光学参数经过实测校准，也不证明城市峰值或事件时窗已经收敛。

## 导入记录

最多2MB、2–2000条。时间必须严格递增且包含Z或时区偏移；angle_deg为0–50度，可选target_deg同范围。仅在浏览器本地处理，文件不会上传。

```csv
timestamp,angle_deg,target_deg
2026-10-25T15:00:00+08:00,0,0
2026-10-25T15:00:01+08:00,3,30
2026-10-25T15:00:02+08:00,6,30
```

也支持相同字段的JSON数组，或对象的records数组。回放只映射角度，城市太阳日期／时刻保持独立。导入只验证格式，不验证仪器校准或数据真实性。未接入的锁扣与设备状态保持未知。

## 街景渲染（2026-11-02）

默认打开中环鸟瞰，可切换沿街视角、展开场景，并开关建筑装饰、光束辉光和HDR柔光。370栋建筑在桌面与手机上均保留原始平面轮廓、孔洞和主体高度；不再把远处建筑替换为包围盒。按距离和设备减少装饰细节，实例化批量绘制窗框、檐口、雨篷、屋顶设备、路灯、树木和静态车辆。

`js/city-scene.js`负责米制分格立面、街道和环境反射探针；`js/render-effects.js`负责HDR阈值柔光和沿已计算光路绘制的摄像机朝向辉光。玻璃采用PBR与一个128px局部环境探针，时间或建筑改变时重新捕获街景，经PMREM预滤后用于粗糙反射；它不是每一块玻璃的精确反射或全场景路径追踪。太阳方向仍来自原太阳几何；太阳阴影、雾、反射和色调随时刻变化。手机默认关闭柔光，保留可手动开启的选项。

**数据边界：**立面材质、装饰、屋顶设备、雨篷、车辆、绿化与路灯均为程序化示意，并非现场逐栋重建。道路宽度沿用原数据的估计值。示意物件只进入图形渲染，不加入光路求交；装饰造成的阴影也不等于光学求解器已经评估这些物件的遮挡。光束的宽度、辉光和HDR输出不表示辐照度、功率或眩光严重度。关闭渲染效果不会改变光源、交点、分支或能量账目。

Three.js图形接口参考：[PBR材质](https://threejs.org/docs/#MeshStandardMaterial)、[实例化](https://threejs.org/docs/#InstancedMesh)、[环境预滤](https://threejs.org/docs/#PMREMGenerator)。依赖仍固定为仓库内的r170，不使用在线模型或额外追踪服务。

街景测试进一步检查所有主体轮廓与高度跨设备一致、孔洞保留、求解几何不被渲染修改、装饰生成可复现，以及实例矩阵／顶点的有限性。阴影在太阳、场景或建筑变化后更新；静态画面按需重绘，避免持续重算阴影和反射。
